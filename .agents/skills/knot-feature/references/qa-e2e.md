# QA (E2E) 절차

한 문장 책임: QA 시트의 시나리오를 E2E 테스트로 옮기고 CI에서 돌린다. 사람이 직접 부르는 스킬이
아니다.

| 읽기 | 쓰기 |
| --- | --- |
| QA 시트 | E2E 코드, QA 시트 결과 칸 |

## 메시지

- 받는 메시지: 없음. 서브 에이전트가 아니라 FE 구현 하네스가 구현을 마친 뒤 그대로 수행하는
  절차다. 사람도 입구 스킬도 부르지 않는다.
- 보내는 메시지: 없음. 결과는 FE 구현 하네스의 PR 본문에 들어간다.

## 규칙

- QA를 하는 수단이 E2E 테스트이고, E2E에는 사용자 여정 시나리오가 담긴다. 이것만 통과하면 기능
  요구사항이 충족된 것이다.
- QA 체크리스트 DB https://app.notion.com/p/40291cc013ea43a0854771144e94d014 에서 이슈의 「노션
  변경 사항」에 적힌 행과 같은 요구사항 ID의 행을 찾는다. 행마다 E2E로 볼 수 있는지 판단하고,
  테스트 이름에 행 ID를 넣는다. E2E로 볼 수 없는 행(실제 서버 응답이 필요한 경우 등)은 PR의
  「관련 QA」에 이유와 함께 적는다.
- 위치는 `frontend/src/__test__/<페이지 이름>.test.ts`다(`frontend/.claude/rules/test-strategy.md`).
  API 응답은 msw mock으로 고정한다.
- PR #855가 머지된 뒤에는 `knot-qa` 스킬의 준비 단계, `frontend/.claude/skills/qa-e2e`, PR 템플릿
  「관련 QA」, `.github/workflows/frontend-e2e.yml` 관문을 그대로 쓴다. 머지 전에는 같은 규칙을
  이 문서대로 수행한다.
- PR CI에서 E2E를 돌리고 통과하지 못하면 PR이 막힌다. 이 CI 실행이 QA 단계이며, FE 구현
  하네스는 그 결과를 확인한 뒤에야 PR URL을 돌려준다. 필수 검사 지정은 유월이 정한다. 배포 뒤
  QA는 이 흐름에서 다루지 않는다.
- QA 시트 결과 칸: E2E 결과를 자동으로 기록하는 경로(GitHub에서 노션으로)가 아직 없으면 결과
  칸을 비워 두고 PR에 「자동 확인 미연결」이라고 적는다. 추측으로 판정을 적지 않는다.
- E2E 시나리오 설명은 사람이 PR에서 읽는다. 설명만 읽어도 어느 요구사항을 검증하는지 알 수 있게
  쓴다. 가능한 한 문구가 아니라 역할이나 테스트 ID로 요소를 잡는다.

## 하지 않는 것

- 노션 QA 시트에 새 시나리오 행을 만들지 않는다. 그 일은 문서 단계의 QA 시트 서브 에이전트가 한다.
- 다른 서브 에이전트를 부르지 않고 사용자에게 직접 묻지 않는다.
