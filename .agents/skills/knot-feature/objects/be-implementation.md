# BE 구현 하네스 (객체)

한 문장 책임: 이슈, 도메인 규칙, API 명세를 직접 읽어 백엔드를 구현하고, 단위 테스트와 통합
테스트를 만든 뒤 PR을 올린다. 컨벤션은 기존 백엔드 rules와 스킬에서 가져온다.

| 읽기 | 쓰기 |
| --- | --- |
| 이슈, 도메인 규칙, API 명세, QA 시트 | `backend` 코드, PR |

## 받는 메시지

| 보내는 쪽 | 메시지 | 조건 |
| --- | --- | --- |
| 입구 스킬 | 이슈 URL 전달, 「구현해라」 | 완료 조건이 「개발까지」일 때만 |

## 보내는 메시지

| 받는 쪽 | 메시지 | 조건 |
| --- | --- | --- |
| 입구 스킬 | PR URL | 구현과 PR이 끝났을 때 |

## 규칙

- 자율적인 객체가 아니다. 다른 객체에게 메시지를 보내 정보를 받지 않고 GitHub 이슈, 노션 도메인
  규칙, API 명세, QA 시트에 직접 접근해 스스로 처리한다.
- 이슈 본문의 「노션 변경 사항」 링크가 정본 위치다. 백엔드는 이슈, 도메인 규칙, API 명세로
  구현한다. 순서는 도메인 규칙, API 명세, 소스 코드다. 관련 원문을 찾는 절차는
  `backend/docs/notion-context.md`를 따른다.
- 기존 백엔드 하네스를 그대로 쓴다. `backend/`에서 시작하고 `backend/.agents/skills/knot-commit`,
  `knot-pr`, `knot-api-spec`의 `SKILL.md`를 경로로 직접 읽는다. 코드 규칙은 `CONTRIBUTING.md`의
  Java 가독성 규칙과 Spotless를 따른다. 브랜치는 `be/<type>/#<이슈 번호>`이고 워크트리에서
  작업한다.
- 테스트는 반드시 있다. 단위 테스트는 함수 단위로, 통합 테스트는 구현에 필요한 것을 알아서 만들고
  돌린다. TDD 적용 여부와 세부 방식은 이 하네스 안에서 정하고 강제하지 않는다. 테스트는 QA
  시트의 시나리오를 근거로 고르되 E2E는 프론트 길이 맡는다.
- 완료 조건 「개발까지」가 `knot-commit`과 `knot-pr`가 요구하는 commit, push, PR 생성의 명시
  요청이다. 커밋에 co-author와 AI 생성 표시를 붙이지 않는다.
- PR은 루트 `AGENTS.md` 「기능 구현 요청 파이프라인」의 PR 공통 규칙을 따른다. 첫 섹션
  `## 노션 변경 사항`에 이슈의 링크를 끌어와 적고, 그 아래는 `knot-pr`의 본문 규칙과 PR
  템플릿을 따른다. 백엔드 PR은 사람이 아니라 AI가 보는 PR이라 내용이 더 많아도 된다. 이슈 라벨을
  그대로 붙이고 assignee를 지정한다.
- PR을 올린 뒤 Backend CI 결과를 확인한다. 실패하면 실패 루프 규칙대로 고쳐 다시 푸시하고,
  통과한 뒤에야 PR URL을 돌려준다. E2E는 프론트 길의 QA 시트 시나리오가 맡는다.
- ADR이 필요한 이슈(`메모`에 ADR 결정과 예정 경로)는 구현 브랜치에서
  `python3 harness/materialize_adr.py <snapshot.json> --issue-number <번호> --implementation --pretty`
  로 `Proposed` ADR을 만들어 같은 PR에 넣는다.
- 실패 루프: 테스트 실패 수정은 3회까지 시도하고, 그래도 실패하면 `blocked`로 멈추고 원인과 시도
  내역을 `question`에 적는다. 구현 중 요구사항이나 명세 문제를 발견하면 문서 단계로 되돌리지 않고
  `needs_user_input`으로 멈춰 입구에 알린다.
- `backend` 밖의 코드는 고치지 않는다. 프론트 변경이 필요하면 `needs_user_input`으로 알린다.

## 반환

`references/return-contract.md`의 규약 그대로. `changed`의 `kind`는 `pr`, `url`은 PR 링크,
`summary`는 브랜치와 포함된 것(구현, 테스트, ADR). `next`는 비워 둔다.

## 하지 않는 것

- 노션 문서를 고치지 않는다. 명세와 코드가 어긋나면 명세를 고치지 않고 `needs_user_input`으로
  알린다. merge 하지 않는다.
- 다른 객체를 부르지 않고 사용자에게 직접 묻지 않는다.
