# 401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

## 상태

Proposed

## 관련 Issue

- #725 [FE] 401을 받으면 토큰을 재발급해 로그인을 이어 가기

## 한 줄 요약

401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

## 왜 이 결정이 필요했나

접근 토큰은 1시간 뒤 만료되고, 백엔드는 refresh 토큰을 회전하며 이미 쓴 토큰이 다시 오면 세션을 끊는다. #551은 처리 위치를 httpClient 인터셉터와 QueryCache · MutationCache onError 중에서 고르고 이유를 남기라고 적었다.

2026-10-16 이스타가 로그인 1시간 뒤 401로 로그인 화면에 가는 문제를 #551보다 먼저 고치기로 했다.

결정 동인:

- 원래 요청을 사용자 모르게 다시 보낼 수 있어야 한다
- Query 밖의 요청과 뮤테이션도 같은 규칙을 따라야 한다
- 같은 refresh 토큰으로 재발급이 동시에 나가지 않게 한 곳에서 막아야 한다

## 트레이드 오프

- httpClient 응답 인터셉터: 모든 axios 요청을 한 곳에서 재발급하고 다시 보낸다. axios 밖의 요청(SSE fetch)은 따로 다뤄야 한다
- QueryCache · MutationCache onError: Query 단위로 실패를 알 수 있지만 원래 요청을 그대로 다시 보낼 수 없고, Query 밖의 요청을 잡지 못한다

## 무엇을 결정했나

401을 받으면 httpClient 응답 인터셉터에서 토큰을 재발급하고 원래 요청을 한 번 다시 보낸다

원래 요청을 다시 보낼 수 있는 곳은 요청 계층뿐이고, 재발급을 한 번씩만 실행하는 잠금도 한 곳에 있어야 한다.

## 결과

- 모든 axios 요청이 401 뒤 한 번 다시 시도된다
- SSE 요청은 이 인터셉터를 거치지 않아 따로 다뤄야 한다
- #551의 전역 401 처리는 이 인터셉터가 원래 401을 던진 뒤에 붙는다

## 다시 논의해야 할 조건

- #551에서 전역 401 처리를 붙일 때
- SSE 요청에도 재발급이 필요해질 때
- 백엔드가 재발급 방식(회전 · 재사용 감지)을 바꿀 때
